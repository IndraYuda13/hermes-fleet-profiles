# Safe editorial publication

- Inspect the actual publishing function before invocation; documentation examples may have obsolete signatures or hide immediate production side effects.
- Compare touched local listing and sitemap bytes with fresh live readbacks before assembling a release, then back up the baseline and recheck concurrency immediately before upload.
- Isolate artifact generation when legacy generators fabricate view counters, restore removed sidebar links, invoke unsupported indexing workflows, or alter unrelated registries. Do not silently repair shared application source outside the technical owner's boundary.
- Align visible publication time with timezone-aware structured publication metadata, and ensure dateModified is not earlier than datePublished.
- Independently review exact staged hashes before deployment; retain the verdict handle and repeat invalidated checks after repairs.
- For general news, submit the sitemap through Search Console on the explicit intended property and read back the exact sitemap. Do not use Google's JobPosting/BroadcastEvent Indexing API as a news crawl-priority request.
- Verify public bytes, licensed photo credits, listing membership, schema, lazy-image loading after scrolling, and mobile/desktop document widths. Separate DOM checks from screenshot pixel inspection and state both limits.
- After an RPC timeout, inspect existing artifacts and live URLs before retrying a publication; timeout is not proof that no external write occurred.
