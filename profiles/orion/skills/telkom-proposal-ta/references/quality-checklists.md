# Quality Checklists

## A. Research-logic checklist

- [ ] The problem is concrete and bounded.
- [ ] Important factual claims have credible sources.
- [ ] The research gap is derived from literature/evidence.
- [ ] The problem formulation follows from the background.
- [ ] Every objective maps to a problem.
- [ ] Every method step maps to an objective.
- [ ] Data/resources needed by the method are available or have a fallback.
- [ ] Evaluation actually measures the objective.
- [ ] Expected contribution does not exceed what the evaluation can support.
- [ ] Assumptions and boundaries are explicit.
- [ ] Feasibility fits the available semester/time/resources.

## B. Background checklist

- [ ] Context is relevant to the exact TA problem.
- [ ] Problem evidence is specific, not generic hype.
- [ ] Impact/importance is explained.
- [ ] Prior work is cited and synthesized.
- [ ] Limitations/gap are explicit.
- [ ] The proposed direction follows logically.
- [ ] No unsupported claims such as “belum pernah diteliti”.
- [ ] Meets the bundled guide's minimum 1-page requirement if current class rules do not override it.

## C. Literature-review checklist

- [ ] Main references are credible and relevant.
- [ ] Literature addresses the research problem.
- [ ] Literature supports the objective/main idea.
- [ ] Method/algorithm theory is sufficiently covered.
- [ ] Strengths and weaknesses of prior work are compared.
- [ ] Theory/prior work is explicitly connected to the proposal topic.
- [ ] Gap-driving literature is recent enough under the official baseline (within 5 years).
- [ ] Each bibliography entry is cited in text.
- [ ] Each in-text numbered citation maps to a bibliography entry.
- [ ] No fabricated citation metadata.

## D. Method/design checklist

- [ ] Method choice is justified against alternatives where relevant.
- [ ] Input/data requirements are explicit.
- [ ] Preprocessing is described.
- [ ] System/model flow is complete.
- [ ] Evaluation scenario is defined.
- [ ] Metrics/criteria are justified.
- [ ] Baseline/comparison exists when the claim requires one.
- [ ] Risks and resource constraints are identified.
- [ ] No result is written as already observed if work is still planned.

## E. Official-structure checklist

- [ ] Cover
- [ ] Approval page
- [ ] Abstract
- [ ] Chapter 1 - Introduction
- [ ] 1.1 Background
- [ ] 1.2 Problem Formulation
- [ ] 1.3 Objective
- [ ] 1.4 Hypothesis (optional)
- [ ] 1.5 Activity Plan
- [ ] 1.6 Schedule
- [ ] Chapter 2 - Literature Review
- [ ] Chapter 3 - System Design or Model Flow
- [ ] References
- [ ] Appendices if needed

## F. Official-format baseline checklist

- [ ] Times New Roman.
- [ ] Chapter heading 16 pt.
- [ ] Subchapter heading 14 pt.
- [ ] Lower heading levels 12 pt.
- [ ] Body 12 pt.
- [ ] Body spacing 1.5.
- [ ] A4 for hardcopy / PDF for softcopy as instructed.
- [ ] Left margin 4 cm.
- [ ] Verify top/right/bottom margins against the current template because the bundled guide contains an internal wording conflict.
- [ ] Formal Indonesian.
- [ ] Avoid first-person pronouns in proposal prose except quotations.
- [ ] Abstract keywords <= 6.
- [ ] Verify current reference minimum because the bundled guide contains 10-vs-20 inconsistency.

## G. Pre-DE red-team checklist

- [ ] Can the problem be stated in one sentence?
- [ ] Can the gap be defended with at least 2-3 concrete prior-work comparisons?
- [ ] Is the objective measurable?
- [ ] Is the method the best fit, not just familiar?
- [ ] Can the data be obtained legally and on time?
- [ ] Is the evaluation feasible?
- [ ] What happens if the main method underperforms?
- [ ] What is the smallest defensible contribution?
- [ ] Which claim is easiest for a reviewer to attack?
- [ ] Which assumption would invalidate the study if false?

## H. Seminar checklist

- [ ] Story flows problem -> gap -> objective -> method -> evaluation.
- [ ] Slides do not contain dense paragraphs.
- [ ] One visual summarizes the research flow.
- [ ] Literature comparison is visible, not hidden in narration.
- [ ] Every method choice has a short reason.
- [ ] Dataset/system context can be explained precisely.
- [ ] Expected outcome is not presented as an achieved result.
- [ ] Prepared answers exist for scope, novelty/contribution, method choice, baseline, metric, data, feasibility, and limitations.

## I. Revision checklist

- [ ] Each reviewer/supervisor comment has a tracked disposition.
- [ ] Changes did not create contradictions elsewhere.
- [ ] New claims introduced during revision have sources.
- [ ] Terminology is consistent after edits.
- [ ] Abstract was updated after body changes.
- [ ] Figures/tables and cross-references remain correct.
- [ ] References remain synchronized.
